# D04-B2.6 — Reliability implementation and release gate

## Review-only implementation
- Migration `20261014000000_document_reconciliation.sql`: service-role RPCs for lease fencing, stale processing claims and abandoned pending failure.
- Finalizer rechecks lease before uploading the verified source.
- `deal-document-reconcile` is a secret-protected maintenance endpoint, disabled by default.
- Worker processes at most 25 expired processing rows, 25 old pending rows, and 25 stale ready/failed rows per invocation.
- Expired processing with a valid final source is promoted to READY via token-checked RPC.
- Expired processing with no source remains processing for a later retry or manual review.
- Pending older than 3 hours becomes FAILED via conditional RPC.
- Quarantine for READY/FAILED records older than 4 hours is deleted; source is never deleted by the worker.

## Known blockers — do not enable uploads or schedule worker yet
1. **Lease fencing is not atomic with Storage upload.** A worker can lose its lease after the pre-promotion check but before Storage commits. True cross-service fencing requires a different upload/promotion protocol or a longer, bounded execution guarantee plus verified concurrency tests.
2. **Crash after promotion.** Reconciliation handles a valid source but may need manual intervention for corrupt or inaccessible sources.
3. **Recovery scope.** Failed rows do not transition to pending; users must initiate a new upload.
4. **Quarantine overwrite**: Verify signed upload semantics and RLS behavior in a non-production Supabase project.
5. **Scheduling not configured**: A secured recurring invoker (e.g. Supabase Cron) must be configured separately after validation. Never expose TRIPP_RECONCILER_SECRET.
6. **Tests not executed**: Deno and live Supabase test runs are outstanding.
7. **File validation**: PDF/DOCX structural checks are not a complete malware or content safety assessment.
8. **Storage listing and token lifetime**: Verify signed-upload expiration and safe retention before enabling cleanup.
9. **Migration order**: Apply D04-B2.5 before D04-B2.6 only after reviewing live schema. No migration history table exists in the current project.
10. **Execution limits**: Worker downloads up to 20 MiB per source, up to 25 records; runtime memory and time budgets require measurement.

## Mandatory negative tests
- Two simultaneous finalizers: only one claim.
- Stale lease token cannot complete.
- Recovery worker without secret or disabled flag: denied.
- Worker with expired lease and valid source: READY after revalidation.
- Worker with absent source: not READY.
- Cleanup never deletes `source.pdf` or `source.docx`.
- A stale quarantine credential cannot alter a READY source.
- Cross-org access denied; viewers cannot upload.
- Crash at every transition and concurrent worker invocations are safe.
- Signed-upload transport works with restrictive Storage RLS without broadening client privileges.

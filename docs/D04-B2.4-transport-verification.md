# D04-B2.4 — Upload transport verification gate

## Status
Review-only. Do not enable `TRIPP_ENABLE_DOCUMENT_UPLOADS=verified` until every live negative test passes.

## Security invariant
A signed upload token is issued only for `org/deal/document/quarantine.ext`.
Metadata `storage_path` is `org/deal/document/source.ext`.
Only a trusted backend with service-role credentials can create `source.ext`, with `upsert:false`.
The quarantine token must never be accepted for `source.ext`.

## Deployment preflight
1. Confirm Supabase Edge Functions supports `npm:@supabase/supabase-js@2`, Deno.serve, and the project's configured auth/JWT gateway.
2. Confirm `SUPABASE_URL`, `SUPABASE_ANON_KEY` (or publishable key), and `SUPABASE_SERVICE_ROLE_KEY` are configured as server secrets; never copy them into browser code.
3. Confirm `tripp-deal-documents` is private with 20 MiB limit and PDF/DOCX MIME allowlist.
4. Confirm restrictive Storage browser-deny policy is present.
5. Confirm signed upload token works against the restrictive policy without modifying it.
6. Verify the Edge Function and Storage platform upload size limits. No 20 MiB transfer guarantee is made before a live test.

## Required executable live cases
- No bearer token -> 401; invalid token -> 401.
- Nonmember, wrong organization, wrong deal -> no metadata or Storage access.
- Viewer cannot initiate/finalize; admin/member can.
- Missing/oversized/unsupported file metadata rejected.
- Signed quarantine token cannot upload to source path.
- Signed quarantine token cannot overwrite source after successful finalization.
- A second signed upload of quarantine must not alter the finalized source.
- Finalization before upload -> 409; malformed PDF/DOCX -> 422; size mismatch -> 422.
- Valid PDF and valid DOCX must pass; ZIP bombs, traversal and macro DOCX must fail.
- Finalization replay must not replace the source.
- Failure after source creation but before metadata READY requires reconciliation; do not delete source blindly.
- Concurrent finalize attempts and stale quarantine credentials must not modify ready bytes.
- Check cleanup of abandoned pending rows and quarantine objects; ensure an expiry/reconciliation job exists.
- Confirm signed URL downloads only expose ready, correctly scoped objects.

## Deployment blockers
- Live transport behavior and RLS compatibility not verified.
- Concurrent finalization locking/reconciliation not yet implemented.
- Quarantine expiry and abandoned pending cleanup not yet implemented.
- DOCX structural validation is not full OOXML semantic validation or malware scanning.
- PDF structural validation is not full parsing or malware scanning.
- Unit tests are committed but have not been run in a Deno runtime.
- The feature flag remains disabled by default.
